# 內容維護指南（給非工程人員）

> 這份文件寫給負責維護網站內容的人，**不需要任何程式知識**。
> 對應 SAI 附錄 E「Non-developer content maintenance guide」。
>
> 目標：登入後台後，在 3–5 分鐘內完成一般的新增或編輯。

---

## 登入

網址：`https://<網站網址>/admin/login`

前台頁面刻意不放「管理員登入」連結，請把這個網址加入書籤。

- 帳號密碼由系統管理者以指令建立
- 連續輸入錯誤 5 次會暫時鎖定 15 分鐘（防止他人猜密碼）
- 登入後 8 小時會自動登出

**忘記密碼**：無法自行重設，請聯絡系統管理者執行
`flask admin reset-password`。系統刻意不做 email 重設功能。

---

## 後台總覽

登入後看到儀表板，分成五個區塊：

| 區塊 | 用途 |
| --- | --- |
| 快速操作 | 一鍵新增研究成果／在學成員／畢業生 |
| 內容狀態 | 各類內容的「已發布／草稿」數量，點擊可篩選 |
| 需要注意 | 缺圖片替代文字、缺英文標題、缺描述等品質提醒 |
| 最近修改 | 最近 10 筆變更，可直接跳回該內容 |
| 系統狀態 | 資料庫、上傳目錄、最後備份時間 |

「需要注意」只是提醒，**不會**阻止你儲存草稿。

---

## 三種內容狀態

| 狀態 | 前台顯示 | 會被 Google 收錄 | 用途 |
| --- | --- | --- | --- |
| 草稿 draft | 否 | 否 | 編輯中，還沒準備好 |
| 已發布 published | 是 | 是 | 正式公開 |
| 已封存 archived | 否 | 否 | 停止展示但保留資料 |

**新建的內容一律是草稿。** 要公開必須按「發布」按鈕。

## 新增在學研究成員

「研究成員 → 新增」

### 必填

- **中文姓名**
- **網址代稱（slug）**：英文小寫，用連字號，例如 `hong-xu-chen`
- **狀態**：在學
- **研究焦點**（中文或英文至少一個）

### 建議填

- 英文姓名、年級／學位、入學年度
- 技能標籤（2–4 個）
- 照片 + **照片替代文字**

### 關於網址代稱

這會變成該成員的固定網址：`/people/hong-xu-chen`

**發布後盡量不要改。** 若真的要改，系統會自動建立轉址，
舊網址不會變成 404，但外部連結與搜尋排名仍可能受影響。

### 照片

- 格式：jpg、png、webp
- 上限 8 MB
- 系統會自動縮放並移除相機的 GPS 等隱私資訊
- **有照片就必須填替代文字**，否則無法發布

替代文字寫法：描述照片內容，例如「陳泓序在光學實驗室操作量測設備」。
不要寫「照片」或「圖片」。

### 發布

填完按「儲存」，再按「發布」。
若有缺漏（例如有照片但沒填替代文字），系統會顯示原因並拒絕發布。

## 新增研究成果

「研究成果 → 新增」

### 必填

- **類型**：期刊論文／會議論文／專案／原型／模擬／資料集／其他
- **年份**
- **標題**（中文或英文至少一個）
- **網址代稱**
- **摘要**（中文或英文至少一個）

### 摘要怎麼寫

約 80–180 字，說清楚四件事：

1. **問題**：想解決什麼
2. **方法**：怎麼做的
3. **結果**：得到什麼
4. **意義**：為什麼重要

這是整個網站對搜尋引擎與 AI 最重要的內容。寫得清楚，
別人才找得到、引用得到。

**不要寫**「效果良好」「具有重要意義」這類空話 ——
要寫具體數值與可驗證的事實。

### 分段欄位

「問題／方法／結果／貢獻與限制」四個欄位可分別填寫，
前台會分段呈現。論文類建議至少填「方法」與「結果」。

### 發表資訊

- **期刊／會議名稱**
- **DOI**：有正式論文才填，系統會檢查格式
- **外部連結**：出版社頁面、專案網站
- **GitHub**：程式碼

**沒有的欄位就留空。不要填猜測的內容。**

### 關聯研究成員

在「相關人員」選擇實驗室成員。選了之後：

- 成果頁會顯示成員並連到個人頁
- 成員個人頁會顯示這筆成果

這個雙向關聯是網站價值的核心，請務必設定。

外部共同作者不需要建立成員資料，寫在「作者列表」文字欄即可。

## 學生畢業（在學 → 畢業生）

在該成員的編輯頁按「轉為畢業生」。

系統會要求填寫：

- **畢業年度**
- **學位**
- **論文題目**（若已填會沿用）

轉換後：

- 個人網址**不變**（外部連結不會失效）
- 研究成果關聯**完全保留**
- 從「研究成員」頁消失，出現在「畢業生」頁
- 系統自動記錄這次操作

### 畢業後的就業資訊

「現職單位」與「現職職稱」**只有在本人同意公開時才填**。
留空就不會顯示。這是隱私要求，不是選填欄位而已。

## 網站設定

「網站設定」分成幾個分頁：

| 分頁 | 內容 |
| --- | --- |
| 實驗室基本資料 | 中英文名稱、學校、系所、**校徽／Logo** |
| 首頁 | 主標題、簡介、主視覺圖片、研究方向列表 |
| 聯絡與招募 | Email、地址、地圖連結、招生說明 |
| SEO 預設值 | 網站標題後綴、預設描述、社群分享預設圖 |
| 進階 | robots 政策、llms.txt 開關 |

### 上傳校徽

「實驗室基本資料 → Logo」上傳。上傳後會出現在網站左上角與瀏覽器分頁圖示。

> 校徽屬校方識別資產，使用前請確認符合學校的識別規範。

### 研究方向

首頁與「關於」頁的研究方向列表在這裡維護。
建議 3–6 項，每項一句話定義。

### 招生說明（重要）

導覽列的「加入我們」頁面內容在「聯絡與招募」維護。
請具體寫明：

- 招生簡章**什麼時候**發布
- 在**哪裡**發布（系所網站、校方招生網頁的實際網址）
- 有興趣的學生該**怎麼聯絡**

寫「歡迎加入」沒有幫助；寫「每年 10 月於系所網站公告，
有興趣請先來信附成績單與研究興趣說明」才有幫助。

### 進階：llms.txt

這是給 AI 系統讀的實驗性檔案。

**它不是 Google 排名的必要條件，也不保證任何效果。**
不確定就保持關閉。

## 刪除政策

系統**預設不提供永久刪除**。

- 不想顯示 → 用「封存」，資料保留，可隨時恢復
- 有關聯研究成果的人物 → 禁止直接刪除，避免產生孤兒資料
- 被內容引用的圖片 → 必須先解除引用才能刪

這是刻意的設計：資料遺失無法復原，隱藏隨時可以還原。

## 內容品質檢查清單

發布前快速確認：

**人物**
- [ ] 姓名正確、狀態正確
- [ ] 研究焦點有實際內容
- [ ] 有照片就有替代文字
- [ ] 外部連結點得開
- [ ] 個資已確認可公開

**研究成果**
- [ ] 標題、類型、年份、摘要完整
- [ ] 方法與結果符合實際內容
- [ ] DOI／連結是真實且點得開的
- [ ] 相關人員已關聯
- [ ] 主圖有替代文字

---

## 最重要的一條規則

**沒有把握的資料就留空，不要填猜測的內容。**

這個網站的價值來自「可被驗證」。一筆錯誤的論文資訊、
一個猜測的畢業去向，傷害的是整個實驗室的可信度，
而且會被搜尋引擎與 AI 系統長期引用。

不確定的時候：留空，或問教授。
