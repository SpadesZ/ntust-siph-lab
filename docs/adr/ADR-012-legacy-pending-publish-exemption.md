# ADR-012 — 母站遷入人物於研究焦點未補齊時的發布豁免

## 為什麼這份 ADR 存在於 `docs/adr/` 而不是 SAI

SAI v1.2（`docs/SAI.md` / `NTUST_SiPh_Lab_SAI_v1.2.pdf`）是**外部交付的規格來源**，
其決策表僅到 **ADR-011**，且該 PDF 不由本 repo 維護、不應被改寫。
SAI §25 要求「未來若新增決策必須另開 ADR」，本檔即為該要求的載體。

> **稽核註記（2026-08-16 交付前審查修正）**
> 本決策原先被記為「ADR-012（見 `docs/SAI.md`）」，但 SAI 中並不存在 ADR-012。
> 那是一個指向不存在文件的懸空引用，使豁免的權威來源無法被查證。
> 同時，原核准紀錄的日期（2026-08-14 / 2026-08-15）與實際取得裁示的日期不符。
> 本檔取代該引用，並記錄真實的核准來源與日期。

## 1. 背景：兩條 SAI 規格互相衝突

| 規格 | 要求 |
| --- | --- |
| §15.1 發布門檻 | Current Member 發布前 **research focus 為必填** |
| §2.3 / §23.1 | 母站不存在的資料（研究方向、英文姓名）**Agent 不得猜測填入** |
| AC-23 | 四位碩二生姓名**必須能在新站被找到** |

母站（`https://sites.google.com/view/ntust-siph-lab/`）對 LC-015 ~ LC-018
四位碩二生**只提供姓名與年級**，沒有研究方向。

因此三條規格無法同時滿足：

- 若照 §15.1 不發布 → **AC-23 失敗**（四人在新站查不到）。
- 若填入推測的研究方向以通過門檻 → **違反 §2.3**，且是 SAI 全篇最嚴格禁止的一類錯誤。

這是規格層級的衝突，**不是實作可以自行解決的問題**，必須由管理者裁示。

## 2. 裁示

| 項目 | 內容 |
| --- | --- |
| **決定** | **發布四位成員，缺漏欄位標記為待補** |
| 核准人 | 研究室管理者（本專案委託人） |
| 核准日期 | **2026-08-16** |
| 核准依據 | 委託人於 2026-08-16 交付前審查的回覆中明確裁示 |
| **委託人原話** | 「可先發布，反正後端管理員能修改」 |
| 委託人理由 | 研究方向可由管理者日後於後台自行補齊，不需為此阻擋上線 |

> **重要**：以上「委託人理由」即為委託人本人陳述的完整理由，
> 未經審查者潤飾或擴充。任何額外的工程論證都必須標示為審查者補充，
> 不得混入核准紀錄冒充委託人意見（此為 ADR-011 的核心要求）。

## 3. 實作方式

```
people.legacy_pending_detail = True
```

`PublishValidator.validate_person()`（`app/services/publish_validator.py`）
對帶有此旗標的人物，把「研究焦點必填」由 **error 降級為 warning**：

- **error** 會阻擋發布；**warning** 不阻擋，但持續顯示。
- Admin Dashboard 的「需要注意」區塊會持續列出，直到補齊為止。
- 補齊後 `PersonService._assign_fields()` 會**自動解除**旗標
  （`person_service.py:255`），避免永久噪音。

### 豁免範圍（不得擴張）

| 欄位 | 是否豁免 |
| --- | --- |
| `research_focus_zh` / `research_focus_en` | ✅ 豁免（本 ADR 唯一授權項） |
| 姓名 `name_zh` | ❌ 不豁免 |
| `slug` | ❌ 不豁免 |
| 照片 `alt`（AC-12） | ❌ 不豁免 |
| 外部連結格式 | ❌ 不豁免 |

任何把此旗標用於上表以外欄位的行為，都**不在本 ADR 授權範圍內**，
需另開 ADR。

## 4. 後果與後續責任

- **正面**：AC-23 與 §2.3 同時滿足，不需二擇一犧牲其中之一。
- **代價**：四個人物頁的內容深度暫時不足，對 SEO/GEO 的貢獻有限
  （§13.1 Fact density）。這是已知且被接受的取捨。
- **後續責任**：研究室提供四位成員的研究方向與英文姓名後，
  由管理者於 `/admin` 補齊。**不需要改程式**。
